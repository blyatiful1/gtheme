# NIGHTBLOOM — the glasshouse after dark

A Victorian glass conservatory at night. Deep green dark instead of black,
bioluminescent jade as the working colour, and exactly one amber firefly on
every surface — the terminal cursor, the prompt arrow, the dot under a running
app in the dock. Violet grow-lights are rare and deliberate. Nothing is pure
black and nothing has a visible window border.

## What applying this Look does

- Sets the wallpaper to the glasshouse picture, on both the desktop and the
  lock screen, over a deep-green base colour.
- Switches the desktop to dark, green highlight, Papirus-Dark icons and the
  adw-gtk3-dark theme so older apps match the newer ones.
- Sets the system fonts to Adwaita Sans and Monaspace Neon.
- Installs the Nightbloom shell theme and turns it on.
- Configures ten add-ons: glass blur behind terminals, a bottom dock with amber
  running dots, no window borders, faster shell animations, wobbly windows, the
  flower emblem in the top-left menu, and the hot bottom edge.
- Writes a complete Ghostty configuration — the terminal theme, the glass CSS,
  and both custom shaders.

It changes settings and copies files. It cannot run a program on your computer.

## What this Look does NOT include

The rice this Look came from is a hand-run repository with a README as its
manual. Several of its parts are not files-and-settings, so they cannot be a
Look at all. They are named here rather than quietly dropped.

**The live video wallpaper.** The original plays a 19-second 4K loop through the
Hanabi add-on. That clip is a personal-use download that may not be passed on,
so it is not here and neither is the frame that used to stand in for it. This
Look ships its own picture instead — see *The wallpaper* below — and Hanabi is
enabled with no video assigned. If you supply your own loop, point Hanabi at it
and the picture becomes the fallback for when Hanabi is off, which is how the
original was built to degrade anyway.

**`rebloom` — the matugen reseed engine.** The original can re-hue its whole
palette from a colour or a photograph, writing parallel `*-dynamic` files
through a set of templates, with a documented rule about which colours grow
from the seed and which never drift (a firefly is a firefly whatever the plants
are doing). That is a program with its own dependency on `matugen`. A Look is
declarative, so `rebloom` stays where it is.

**Vesktop (Discord).** Enabling its theme means editing a live JSON settings
file in place — reading an array, adding an entry, writing it back. A Look
copies whole files; it does not surgically edit somebody's app settings.

**Zen Browser.** Its `userChrome.css` deploys into a profile folder whose name
contains a random per-installation id. There is no portable path to write to.

**Spotify / spicetify.** spicetify patches the Spotify application bundle
itself and has to be re-applied after Spotify updates. That is out of scope for
a Look by a wide margin.

**Ghostty by symlink.** The original points `~/.config/ghostty` at the rice
repository, so editing the repo edits the live config. This Look copies real
files instead. If your `~/.config/ghostty` is a symlink into another project,
gtheme will tell you so and ask before taking it over, rather than writing
through the link into somebody else's repository.

**The terminal toys.** `ttfx`, `termflix`, `cbonsai`, and the `nightbloom-*`
scripts behind the fish greeting are programs, installed with `cargo` and from
the AUR. Looks do not ship or run programs.

**btop, cava, fastfetch, yazi, television, starship, fish and Alacritty
themes.** Left out to keep this Look to the desktop itself. They live in the
original rice.

**`intellibar`.** The auto-hiding top bar is a private add-on written for this
machine and published nowhere. It is listed here as a *local-only* add-on: if it
is installed, this Look turns it on; if it is not, gtheme says so plainly and
applies everything else. A Look never carries add-on code.

**The Burn My Windows profile.** The original points the add-on at a profile
file whose name is a timestamp generated on one machine. Not portable, so not
included.

**The boot splash and anything needing an administrator password.** Never part
of a Look.

## The wallpaper

`wallpaper/nightbloom-glasshouse.png` is drawn, not photographed: a lit glass
conservatory standing across still water on a green night, in this Look's own
palette. It is generated by `tools/gen_nightbloom_wallpaper.py` in the gtheme
repository, so it carries the project's licence and nobody else's — run the
script and the same file comes back.

It replaces the picture an earlier draft of this Look used, which was a frame
of somebody else's video, licensed for personal desktops only. A Look is a
thing you hand to strangers, so it may only carry pictures that can be handed
to strangers.

### Using your own picture instead

Nothing here is precious. To point the Look at your own wallpaper, put the file
in this folder and change the two places that name it in `theme.toml`:

```toml
[[files]]
src = "wallpaper/my-picture.png"
dest = "~/.local/share/backgrounds/nightbloom/my-picture.png"
```

and the three `picture-uri` settings further down, which all read
`file://{{ home }}/.local/share/backgrounds/nightbloom/…`. Keep the file name
the same in both places. `gtheme validate themes/nightbloom` will tell you if
you missed one.

Or skip the file entirely and set the wallpaper the ordinary way in gtheme
after the Look is applied — nothing about a Look is permanent, and Undo puts
back whatever was there before.
